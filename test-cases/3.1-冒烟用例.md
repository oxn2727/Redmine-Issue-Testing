> **这份是「最小可执行验证集」。** 每个功能模块、每个接口各一条，**一遍跑完约 20 分钟**，用来回答一个问题：

### 2.1 Postman 环境（建一次，全程复用）

**省事做法（推荐）**：直接导入已配好的两个文件 —— `postman/` 下的 `Redmine-冒烟（7条）.postman_collection.json` 与 `Redmine_Smoke.postman_environment.json`（Postman 里 `Import` → 把文件拖进去）。**环境变量、4 个 Key、7 个请求、自动断言、`smoke_id` 自动传递全都在里面**，导入后右上角选 `Redmine_Smoke`，按 01 → 02 → 03 → 04 → 05 → 06 → 07 的顺序 Send 即可。

**手动做法**：`Environments → +` → 命名 `Redmine_Smoke` → 按下表填 → `Save`，右上角环境下拉选 `Redmine_Smoke`。

| Variable        | Initial value                              | 说明                                |
| --------------- | ------------------------------------------ | --------------------------------- |
| `base_url`      | `http://localhost:3000`                    | 被测系统地址                            |
| `admin_key`     | `37da63d886132084a9174cfc82d8aa71b9b64c4b` | admin，权限最全                        |
| `reporter_key`  | `7ccb3f452b13be179af51890df67b7155f338f16` | Reporter 角色                       |
| `developer_key` | `2e26af15f157f329150623136aee8c774b672b10` | Developer 角色                      |
| `manager_key`   | `68e4f8f65f56cacef06188684af2221320f4bc02` | Manager 角色                        |
| `smoke_id`      | **留空**                                     | SM-API-02 建完单后写入，给 03 / 04 / 05 用 |

**每个请求四步**：

1. **Method**：按每条标的方法选 `GET / POST / PUT / DELETE`。
2. **URL**：填 `{{base_url}}/...`（`{{ }}` 是 Postman 变量语法；查询参数填在 **Params** 标签，不要手拼在 URL 里）。
3. **Headers**：加 `X-Redmine-API-Key` = 该条指定的 Key。
   - ⚠️ **Key 只能放请求头。** 拼进 URL（`?X-Redmine-API-Key=…`）一定 **401** —— Redmine 不读查询参数。
   - **POST / PUT 必须有 `Content-Type: application/json`** —— 官方原文要求「URL 带 `.json` 后缀也**必须**显式设置」；
   - Postman 里 Body 选 `raw → JSON` 时会**自动带上**这个头，手动再写一遍也不冲突。
4. **Body**（仅 POST / PUT）：选 `raw` → 右侧下拉选 `JSON` → 粘每条给的 JSON。

> **本地环境的坑**：系统若开着代理（`127.0.0.1:7890`），`localhost` 可能被转发出去导致连不上。→ Postman 里关掉 `Settings → Proxy → Use system proxy`，或把 `localhost` 加进 bypass 列表。

**返回 401 怎么查**（401 = 服务端收到了请求，但**没认出 Key**；不是"Key 过期"）：

| 排查顺序 | 现象 | 原因 |
|:--:|---|---|
| 1 | Postman 里 `{{admin_key}}` 显示成橙色 / 红色 | **右上角没选环境** → 变量不被替换，`{{admin_key}}` 原样发出去了。**最常见的一条** |
| 2 | 变量名写错 | 必须叫 `admin_key`，写成 `admin-key` / `adminKey` 都不认 |
| 3 | URL 里出现 `…/users/current.json?X-Redmine-API-Key=…` | **Key 被当成查询参数发出去了。** Redmine **只从请求头读 Key**，拼在 URL 里必 401 —— 实测：同一串 Key，放 URL → 401，放 Header → 200。修法：Postman `Authorization` 里把 `Add to` 改成 **`Header`**（Key 名 `X-Redmine-API-Key`，Value `{{admin_key}}`）；或把 Authorization 设为 **`No Auth`**，改在 **Headers** 标签手加一行 |
| 4 | Key 不是 40 位 | 从响应体/文档里复制时**少贴或多贴了字符** |

> **一步定位**：把 Header 里换成**写死的** `X-Redmine-API-Key: 37da63d886132084a9174cfc82d8aa71b9b64c4b`（不用变量）→ 如果这样就返回 **200**，说明 Key 没问题，是**变量没生效**。
> **区分 401 / 403**：**401** = Key 没认出来；**403** = Key 认出来了但**没权限**，或**管理 → 设置 → API 没勾选「启用 REST Web Service」**（这时所有接口一律 403，响应体为空）。

**返回 404 怎么查**（404 = 资源不存在；但多数时候是 **URL 里的 id 没被替换出来**）：

| 看 URL 长什么样 | 说明 | 怎么修 |
|---|---|---|
| `/issues/{{smoke_id}}.json` | 变量**根本没被替换**（显示成橙红色）→ 环境没选 | 右上角下拉选中 `Redmine_Smoke` |
| `/issues/.json`（id 位置是空的） | 环境里 `smoke_id` **是空值** | 说明存 id 那一步没成功（常见：跑 SM-API-02 时**还没选环境**，脚本静默没写进去）→ 重跑一次 02，或手动把单号填进 `smoke_id` 的值 |
| `/issues/999999.json` | 就是这个 id 不存在 | **正常**，正式用例 API-37 要的正是这个结果 |

> **一句话**：界面列表里能看见那条单 ≠ 接口能查到那条单。本项目实测 **`GET /issues/220.json` 返回 200** —— 接口报 404 时，**先看 URL 里的 id 到底是什么**，别急着怀疑服务端。
> 导入版集合已加**自检**：`smoke_id` 为空时，03 / 04 / 05 的前置脚本会直接抛错并告诉你原因，不会再让你对着 404 猜。

### 2.3 三条判定规则（不懂就会把正常行为当缺陷）

| 规则 | 说明 |
|---|---|
| **PUT / DELETE 成功 = 204，不是 200** | 有响应体反而不正常 |
| **204 ≠ 改成功** | 无权限 / 非法状态转移也返回 204 → **必须回读** |
| **403 ≠ 接口坏了** | SM-API-07 的期望值就是 403；反过来 **200 才是问题** |

**其余常见码**：`200` 查询 / 列表成功｜`201` 创建成功｜`401` Key 错或缺失｜`403` 无权限，或 REST API 未启用｜`404` 资源不存在｜`422` 字段值非法（响应体 `{"errors":[...]}`）｜`400` 请求体不是合法 JSON。

## 三、冒烟记录的用法
